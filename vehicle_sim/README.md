# 차량 연합학습 장애 시뮬레이터 (SASAFL)

차량 업데이트가 늦거나 오지 않는 39개 예시(9개 패턴, "서버가 받은 모습" 기준)를 **한 맵에서 실제 SASAFL 학습과 함께** 보여 주는 화면.
SASAFL 원본 파일(`methods/SASAFL/*`)은 수정하지 않는다.

## 실행

```bash
# wise-175에서 (FL conda 환경의 python)
/home/wise-175/anaconda3/envs/FL/bin/python vehicle_sim/serve.py --port 8765
# 브라우저: http://localhost:8765  (원격이면 VS Code 포트 포워딩으로 8765를 연다)
```

화면 위쪽 **▶ 시작**을 누르면 world(주행 환경)와 SASAFL(torchrun, 서버 1 + 차량 K)이 함께 뜬다. 3D 맵은 인터넷에서 three.js를 받아 오므로 브라우저에 인터넷이 필요하다.

## 화면

| 영역 | 내용 |
|---|---|
| 왼쪽 **시뮬레이션 맵** | 셀 4개(반경·겹침·사이 음영), 권역 경계, 고속도로·터널, 빌딩 숲(음영 Gilbert), 혼잡 교차로, 어린이 보호구역, 보안 구역, 강우 구역, 집·주차장, 주유소·충전소, 서비스센터(OTA), 진입·이탈 게이트, FL 집계 서버. 차량 색 = 연합학습 상태, 업로드 중이면 기지국까지 선, 서버 도착 시 초록 선 |
| 왼쪽 **유스케이스 39** | 예시별 근거·맵 위치·발생 횟수·차량. 행을 누르면 맵이 그 장소로 이동 |
| 왼쪽 **사건 기록** | 전체 사건(패턴별 필터) |

| 오른쪽 **차량 설정 / 전체 설정** | 차량별 하이퍼파라미터(ECU 배수, 중단 확률, 보관 후 전송, 오염 등)와 통신·에너지·환경·SASAFL 값. "39개 전부 보이기" 프리셋 |

## 구조

```
vehicle_sim/
  simcore/common.py   맵·경로·설정 기본값·39개 유스케이스 목록·파일 입출력
  simcore/world.py    0.1초마다 차량 위치·셀·터널·음영·정차를 계산 → world.json
  fl/fl_entry.py      torchrun 진입점: 시뮬레이션 클래스를 끼운 뒤 원본 Start.py 실행 (+ Dirichlet 분할)
  fl/sim_sasafl.py    SASAFLClient/Server/SASAFL 서브클래스: 원본 로직 + 장애 주입 + 기록
  serve.py            HTTP 서버(표준 라이브러리) + 프로세스 관리
  web/                index.html · app.js(three.js) · style.css
  runs/<시각>/        config.json, world.json, server.json, client_<id>.json, events.jsonl, fl.log
```

## 패턴을 만드는 방법 (서버는 원본 SASAFL 그대로)

| 패턴 | 맵·설정 | 구현 |
|---|---|---|
| 1 아예 안 옴 | 주차(시동 꺼짐), OTA, 보호구역 선점, 계산 중단 확률, 배터리 | 학습을 중간에 멈추고 보내지 않음. **프로세스는 살려 두고 수신은 계속** — 원본은 한 대라도 수신을 멈추면 서버 `dist.send`가 막혀 전체가 멈추기 때문 |
| 2 보내다가 끊김 | 셀 사이 음영, 터널, 핸드오버, 권역 경계, 고속 도플러, 패킷 오류, 배터리 | 전송 시간(모델 크기/대역폭)을 조각 단위로 흘리며 연결 확인, 끊기면 `dist.send`를 하지 않음. SASAFL에는 조각 개념이 없어 서버에선 패턴 1과 같게 보인다 |
| 3 미리 빠짐 | 에너지·데이터 기준, 충전 중만 참여, 보안 구역 | 학습을 시작하지 않음. SASAFL에는 불참 신호가 없다 |
| 4 늦게 옴 | ECU 배수, 셀 동시 업로드 한계, 재전송 대기, 대역폭·강우, 보호구역 연산 점유 | 학습·전송에 지연. 서버는 staleness 감쇄(ζ=0.9)로만 반영 |
| 5 모아서 한꺼번에 | 보관 후 전송 + 터널·음영·주차, TDMA 그룹 | 끊긴 동안 업데이트를 쌓았다가 연결되면 연속 `dist.send`. 원본 서버는 차량당 버퍼 1칸이라 덮어쓰고 같은 라운드에 2번 집계 |
| 6 옛 모델로 학습 | 배포 시점에 연결 없음, OTA | 받은 글로벌 모델을 적용하지 않고 마지막 모델로 학습 → 서버가 버전으로 staleness 계산 |
| 7 내용이 틀림 | 학습률·라벨·가중치 노이즈·업데이트 증폭·버전 오차 | 제시간·정상 형식으로 오염된 업데이트 전송. SASAFL에는 검증이 없다 |
| 8 참여 치우침 | 가용률 주기, 이탈 게이트, 차량 이탈, Dirichlet α, 강우 구역 | 참여 가능 차량·데이터 분포 변화 |
| 9 서버 쪽 문제 | 서버 장애 버튼, quota > 보낼 수 있는 차량, 중복 전송 | 서버 프로세스 종료(복구 경로 없음 → 전체 종료), 무한 대기 감지, 같은 업데이트 2번 |

원본과 다르게 둔 것: (1) 원본의 busy-wait 두 곳에 짧은 sleep(CPU 절약, 동작 동일), (2) **복귀 허용**(전체 설정 `끊긴 차량 복귀 허용`) — 원본은 한 번 빠진 차량이 다시 선택되지 않는다. 끄면 원본 그대로 영구 제외된다.

## 주의
- 실제 학습을 하므로 CPU를 쓴다 (차량 8대 ≈ 프로세스 9개, 1스레드씩). 같은 노드에서 다른 실험이 돌고 있으면 그 실험의 실행 시간이 늘어난다.
- 시간은 실제 시간(1배). 체류 시간·터널 통과·전송 시간은 실제 m·km/h·Mbps로 계산된다.
